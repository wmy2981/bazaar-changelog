# 开发说明

「为什么这么做」与踩过的坑。代码里看得出来的常量、选择器、函数名不在这里重复；
用户可见的行为与限制见 [README.zh-CN.md](../README.zh-CN.md)，开发规则与命令见 [CLAUDE.md](../CLAUDE.md)。

## 挂在思源内部结构上的四处

思源一改就失效。动到它们时，请一并更新这里。

- **集市详情页的版本入口**：思源整块重写详情页，入口只能在重写之后补回去，插一次是不行的；
  入口用 `<button>` 而不是 `<a>`，因为集市的点击委托会丢掉 `<a>` 上的点击。
- **更新按钮**：思源自己的更新流程改不了，只能拦截点击、先弹自己的弹窗、确认后再重放一次点击，
  让它的 loading、列表刷新与错误提示照常跑完。重放是同步的，返回时它的确认弹窗已经建好，必须在
  同一帧里点掉并把元素摘掉 —— 那个弹窗是延迟加类、延迟移除的，只点确认会闪一下。拿不到它的弹窗
  对象时什么也不做，只留一条警告：绝不自己实现一套更新流程。
- **插件设置面板**：移动端打开面板会闪一下，两件事各修一半。软键盘这一半：思源给每个输入框绑
  输入处理时先 `focus()`，而这次 focus 发生在插入 DOM 之前，`Setting.open()` 结尾还会再聚焦正文里
  第一个 `input, textarea`；移动端重写的 `focus()` 不看元素在不在文档里就唤起软键盘，键盘触发的
  adjustResize 改 WebView 高度、整页重排。所以 `openSetting()` 在打开这段时间临时接管
  `HTMLElement.prototype.focus`，只拦 `input` / `textarea`，`open()` 一返回立刻还原 —— 事后
  `blur()`、按祖先节点判断都拦不住先在文档外发生的那一次，用户自己点控件也不经过这段。旧写法
  是给令牌输入框临时加 `readonly`，只管住一个控件，也不覆盖第二次聚焦，别退回去。旧画面那一半：
  入场过渡临时建层、结束时拆层，拆层那一帧 WebView 只能交出旧纹理；`openSetting()` 在打开类落下
  之前给容器挂上 `bazaar-settings-dialog`，样式表据此让容器和 `.b3-dialog__content` 常驻图层。
  两件事都要做：键盘不弹了不代表旧画面不闪，反过来也一样。
- **移动端底部抽屉**：外观、抓手与打开动画都借思源自己的抽屉类，插件只加类名、把高度写成行内值。
  它把抽屉限死在 60vh，而插件默认占大半屏，所以用重复类名压过那条规则，别改成依赖样式表顺序；
  它只支持下拉关闭、还会删掉通用弹窗的缩放手柄，调高度只能自己接手势。关闭时摘掉行内位移让它原生
  的过渡接手；弹出时不自己写动画，先停在屏幕外，等它加上打开类再交回 CSS —— 否则位移会和通用弹窗
  的缩放、淡入同时起步，看着就是弹出时抽一下。弹出这一路**不要跟着思源的 `bindBottomSheetDialog`
  写 `visibility: hidden`**：它那两行是给「等视口稳定」那条路做遮挡的，代价是合成层到打开那一帧
  才建出来，移动端 App 的 WebView 手里只有旧画面，于是每次打开都插进一帧抽屉出现前的整屏画面
  （#29）。抽屉本来就在 `translateY(100%)` 之外，3.8.4 起抽屉模式的遮罩又是全透明的，藏它没有
  意义；样式表里给弹窗容器挂的 `will-change: transform`（三个浮层共用那一组规则）是为了让图层
  从插入那一刻就在。同理，交回 CSS
  时也不用再 `void offsetHeight` 强制回流（那两句也是从思源抄来的）：位移与过渡一次样式更新就位。
  抬手后那一下点击只在真的拖动过时才吃掉，否则每次轻点都被吞掉，提交记录点不开、按钮也反应不了。
  这两组抽屉类到思源 3.8.4 才有，所以 `plugin.json` 的 `minAppVersion` 跟着提到 3.8.4 —— 低版本
  上它会退化成居中、满宽、没有圆角与抓手的普通弹窗，而关闭按钮又都被省掉了。高度只在打开时按视口
  算一次，所以 `resize` 与 `visualViewport` 上各挂了一个监听重新夹 —— 原生那条 60vh 的兜底被插件
  覆盖掉了，视口一变（转屏、软键盘、工具栏收起）就会出现比视口还高的抽屉。

## 取舍与坑

- **「最新」以集市为准**：集市索引按小时级更新，只有用集市下发的版号才和用户在集市里看到的一致，
  比它新的发行版整条不显示。
- **CHANGELOG 与发行说明都走 GitHub 官方域名**：两者同属一处，一个前缀式加速开关就能一起覆盖，
  不必为 CDN 另开一条路。raw 地址不带 ref 会 400，所以固定写 `HEAD`，让 GitHub 解析成默认分支。
- **只有 404（或 200 但正文空白）算「这个路径上没有文件」**：限流、5xx、网络错误只是这次没拿到，
  拿来报「没有」会骗用户。
- **确认「没有 CHANGELOG」比首次超时更耐心**：慢网络下几个 404 也可能擦过首次超时；到点后只要没有
  候选真正失败就继续等，否则用户先看到「超时」、点一次「重新获取」才看到「没有 CHANGELOG」。
- **失败的第二行写人话**：不直接透传 `TypeError: Failed to fetch` 这类原文。兜底那句「网络状况差或
  这个仓库没有 CHANGELOG」只在没有候选真正失败（纯粹是慢）时才用 —— 那时确实没有具体原因可给。
- **取不到一律不换来源**：只有确定「这一版没有发行说明」或「这个仓库没有 CHANGELOG」才换，且来源
  下拉要跟着一起动 —— 正文换了来源而下拉停在旧项，用户看到的提示就和来源对不上。取不到时那条路
  换过去也只是再失败一次，所以留着当前来源，把原因写出来。
- **发行版列表为空不说「这个仓库没有发行版」**：上架集市的包一定有发行版，按「该版本没有发行说明」
  处理就够了，不为它单造一句话。
- **加速配置单独开窗、逐项开关**：地址是实现无关的前缀式反代；分项收成一组（缩进 + 左侧细线 +
  次要色 + 更紧的行距），一眼能看出它们从属于总开关。老的布尔配置读到就迁移成「全开」——当初打开
  它的人要的就是「全部走加速」，迁移后不再写回。缓存键用最终地址，否则改完开关还命中旧结果，
  用户会以为开关没生效。
- **emoji 短代码只在插件自己拼的文本里换**：发行说明与 CHANGELOG 走内核的 Lute，它默认就认
  `:tada:`；提交信息是纯文本，只能自己换。别名表整张打进包里，因为浏览器里拿不到内核那份 Lute，
  而给几十上百行提交逐条调内核接口不现实；认不出的别名原样留着，GitHub 也这样。
- **`<details>` 由插件自己拼**：内核的 Lute 不认原始 HTML，`<details>` 会被转义成一行文字。
  所以先把折叠块挖出来、正文换成占位符，标题与正文各走一次内核，渲染完再按占位符换回去；
  围栏代码块里的 `<details>` 只是示例，扫描时跳过；没有闭合标签时原样交给内核 ——
  那本来就是一段文字，不该被当成折叠块。
- **表格与代码块要自己补一层**：Lute 输出的是裸 `<table>` 与 `<pre><code>`，而 `.b3-typography`
  自己带 `overflow: auto`、表格又按内容撑到 `max-content`，宽表格会把整块正文撑出横向滚动条，
  左右滚动时标题、段落跟着一起跑。所以给每张表套一层自己的滚动容器，正文的 `overflow-x` 收在
  `hidden`；代码块补上思源原生的 `.code-block`（主题里的底色与圆角按这个类走），并把它里面的
  `code` 从 `.fn__code` 那套行内代码样式里摘出来 —— 不摘的话整段代码会变成一行一个 chip、还会
 按 `pre-wrap` 断行。两个滚动容器都要写 `flex: 0 0 auto`：`.b3-typography` 是 column flex，
  滚动容器的自动最小尺寸是 0，内容一长就被压扁 —— 表格整个看不见、代码块只剩一行。
- **代码块的高亮交给思源自己**：`ProtyleMethod.highlightRender(container)` 会按设置里的代码主题加载
  highlight.js 的样式，并沿用 `codeLineWrap`、`codeLigatures` 这些开关 —— 插件另配一套只会和主题对不上。
  它只认 `.b3-typography` 里的 `.code-block code`，语言从 `<pre data-language>` 读，而 Lute 把语言写在
  `<code class="language-x">` 上，所以注入后要把语言挪到 `<pre>` 上、补上 `.code-block`（底色与圆角按
  这个类走），再整块交给它。高亮后 `<code>` 多出 `.hljs`，`.fn__code` 那套行内代码样式就不再命中。
  底色不能自己写死：亮色主题的灰底来自基础主题的 `.b3-typography .code-block`，暗色主题没有这条规则，
  用的是代码主题自己的 `.code-block` 底色 —— 写死 `--b3-protyle-code-background` 会让暗色下永远是一块
  灰的，和集市 README 的代码块对不上。
- **提交记录用 compare 而不是自己过滤 `/commits`**：范围由用户选的两个版本决定，只有 compare 能直接
  给出「head 有而 base 没有」的集合；起点是「不限」时没有可比较的起点，才退回 `/commits`。
- **两个接口的提交方向相反**：compare 旧的在前、`/commits` 新的在前，所以只有走 compare 时才反转，
  无条件反转会让「不限 → HEAD」那一屏从旧到新。
- **截断说明紧跟在「列出 N 条提交」后面**：单独摆一行时在列表下面，要翻过几百行才看得见。
- **哈希列与链接分开**：列宽写在列上而不是链接上，否则哈希右边那一截空白也算链接，点空白会跳去
  GitHub；列留一个最小宽度是为了图标类插件给链接加图标时列自己长，而不是把哈希挤断行。
- **头像与名字装在同一个内联盒里**：各做外层 flex 的子项时，外层一宽就把两者朝两头拉开（手机上
  见过：头像孤零零卡在提交信息与作者之间）。头像图片直接显示、拿不到时由 `error` 摘掉；别改成
  「先藏、`load` 之后再显示」—— `display: none` 的懒加载图片不算接近视口，浏览器可能永远不去取，
  于是永远等不到那次 `load`，到头来一个头像都不显示。
- **提交记录的默认起点是本机已安装版本**：用户关心的是「我这版之后改了什么」；安装版本与集市最新
  相同或取不到时，才退回上一个发行版。
- **只有「正文仅一行 Full Changelog 链接」才算空发行说明**：多一行正文就不算，否则手工写的说明会
  被吞掉。认出来也不是报「没有」，而是拿链接里的范围直接跳到提交记录 —— 那种说明本来只有这段信息。
- **「查看提交记录」只在两种来源都确认没有内容时才给**：只有一个来源缺失时，另一种里的正文照样
  能读，把人引到提交记录只是绕远。
- **引用链接化只改文本节点，不重新解析 Markdown**：正文是内核渲染好的 HTML，再解析一遍会改掉排版；
  代码与已有链接里的文字跳过，`@user` 前面紧挨着字母数字时不算。
- **令牌只发给 `api.github.com`**：看的是最终 URL，开了加速时 URL 落在第三方前缀上，自然不带令牌；
  日志只记长度不记令牌。所谓的「加密」只是不明文 —— 浏览器里拿不到系统密钥环，它挡的是设置文件被
  单独贴出去。
- **只接管本仓库的三类链接**：别的仓库、issue 与单条 commit 的链接照常交给浏览器 —— 插件没有它们的
  本地视图，接管了也只能再打开一次；带修饰键时同样不接管。
- **「在 GitHub 中打开」按当前来源现算地址**：CHANGELOG 要用实际命中的文件路径，拿到之前置灰；
  提交记录在起点为「不限」时指向该端点的提交列表，而不是拼一个无效的 compare 地址。
- **加速下取不到提交不看状态码**：部分反代不代理 compare，回的码五花八门，所以只要开着加速又没拿到
  就多给一句「加速服务可能不支持」；直连时失败多半是限流或网络，那句话会把人带偏，因此不加。
- **失败的提交提示后面挂一个「查看不限到 HEAD 的提交」**：反代一般代理 `/commits`，一键就能绕开
  compare；范围本来就是「不限 → HEAD」时不挂，点它等于重试同一个地址。

## 调试

- **渲染测试窗口**：开着调试模式时，在控制台执行 `bazaarChangelogRenderTest()` 打开，样例按弹窗的
  真实链路（内核 Lute → DOMPurify → 引用链接化）渲染一遍。入口只挂在 `window` 上、调试模式关掉就
  摘掉，设置面板里不给入口。样例里加一类写法时，`tests/dom/rendertest.test.ts` 的语法清单要跟着加，
  否则样例会悄悄退化。
- **预览图**：`assets/preview.css` 从思源源码编译，不手写；预览只画弹窗的常规状态，所以只有动了
  预览画面本身才需要重跑编译与 `npm run preview`。
